# 部署与运行说明

本文说明当前本地开发启动方式，并记录待验收的 Compose 部署配置。P12-B 已在隔离的全新 MySQL 中验证 `sql/init.sql` 建立 19 张表、Backend 启动和健康端点；Docker / Compose 的真实容器运行、路由与数据卷持久化仍待 P12-D 验收。

## 先理解两种方式

| | 开发模式 | Compose 配置（待验收） |
|---|---|---|
| 用途 | 修改代码、调试 | 计划用于组员或演示电脑运行；待 P12-D 验收 |
| 前端 | Vite，默认5173 | 构建后的 dist，由 Nginx 提供 |
| 后端 | 本机 Java 17，8080 | Java 17 容器，内部8080 |
| 数据库 | 本机 MySQL，默认3306 | Compose MySQL，独立数据卷 |
| 浏览器入口 | http://localhost:5173 | http://localhost |
| 需要 IDEA/Codex | 不需要，IDEA可选 | 不需要 |

关闭 Vite 后访问5173出现连接被拒绝是正常的。正式模式不运行 Vite，但同样需要 Docker Desktop 和容器保持运行；电脑关机后不能提供网页服务。

## 【开发模式】

### 1. 首次准备

安装 JDK 17、Node.js 20+、pnpm 和 MySQL 8.0.16+。配置 JAVA_HOME/PATH，确保终端中 java、node、pnpm 可执行。没有 pnpm 可执行 `npm install -g pnpm`。

Maven不需要通过 IDEA 提供：脚本优先使用 PATH 中的 mvn 或 MAVEN_HOME；找不到时自动从 Maven Central 下载固定版本3.9.9、校验 SHA-512，缓存到被忽略的 `.runtime/tools`。首次启动需要联网，后续复用缓存。离线电脑可提前安装 Maven 3.9+ 并设置 MAVEN_HOME。

确认 MySQL 服务运行。Windows服务名称不一定相同，在“服务”中查找 MySQL 并启动；也可以用管理员 PowerShell 执行 `Start-Service -Name <实际服务名>`。脚本只检查服务，不偷偷修改系统服务配置。

全新本机数据库首次初始化：在项目根目录打开 MySQL 客户端 `mysql -u root -p --default-character-set=utf8mb4`，然后执行 `SOURCE sql/init.sql;`。也可以用 Workbench 打开该脚本执行。它是创建 19 张表的 first-run bootstrap；普通启动或已有业务库不要重复执行，也不要再执行 `sql/archive/smart_exam_team_v1.sql` 或历史升级脚本。Compose 的首次空卷配置为自动执行 `init.sql`，实际容器行为待 P12-D 验收。

### 2. 配置环境变量

开发脚本读取 `config/local.env`，已有进程环境变量优先；不读取根目录供 Compose 使用的 `.env`。首次可复制 `config/local.env.example`，已有本地配置不要覆盖：

| 变量 | 开发默认值/要求 |
|---|---|
| DB_HOST | 127.0.0.1 |
| DB_PORT | 3306 |
| DB_NAME | smart_exam |
| DB_USERNAME | root |
| DB_PASSWORD | 必填，本机数据库密码 |
| JWT_SECRET | 必填，至少32位随机 ASCII 字符，不用示例值 |
| ADMIN_USERNAME / ADMIN_INITIAL_PASSWORD / ADMIN_NAME | 首次需要创建 ADMIN 时同时提供；已有 ADMIN 不会重复创建 |
| AI_BASE_URL / AI_API_KEY / AI_MODEL | 可选；三项未配置时仍可启动并使用人工阅卷 |

不要把真实值写入 bat、源码或 README。可以填写被 Git 忽略的 `config/local.env`，或在 PowerShell 中临时设置；以下输入方式不会把数据库密码写到命令历史：

```powershell
$secure = Read-Host '输入本机数据库密码' -AsSecureString
$env:DB_PASSWORD = [System.Net.NetworkCredential]::new('', $secure).Password
$bytes = New-Object byte[] 32
$rng = [System.Security.Cryptography.RandomNumberGenerator]::Create()
$rng.GetBytes($bytes)
$rng.Dispose()
$env:JWT_SECRET = [Convert]::ToBase64String($bytes)
.\start-dev.bat
```

上面密钥只在此终端有效，重新生成会使旧登录令牌失效。长期开发可在Windows“用户环境变量”中保存这两个值，然后重新打开终端；不要把秘密发给他人。

IDEA仍可使用：给 SmartExamApplication 和 Maven Runner 同时提供上述变量，尤其注意现在 JWT_SECRET 不再有共享默认值。不要同时用 IDEA 和脚本占用8080。

### 3. 日常启动、检查、停止

双击或在项目根目录执行：

```powershell
.\check-env.bat
.\start-dev.bat
.\stop-dev.bat
```

三个命令分别是检查、启动、停止，不是要一次连续执行。非交互终端可以加 `--no-pause`。

- 启动检查Java17、Node20+、pnpm、MySQL连通性、秘密和8080/5173占用。
- 后端由独立 Maven 打包，直接以 `java -jar` 运行；前端依赖不存在时先执行 `pnpm install --frozen-lockfile`，然后启动项目本地 Vite。已有依赖不自动清空重装。
- 等待 `/actuator/health` 返回 UP（包含数据库健康）和前端页面可访问后，才显示成功。
- 启动日志在 `.runtime/backend.log`、`backend-error.log`、`frontend.log`、`frontend-error.log`。日志和PID文件不入Git，也不要对外共享未经检查的日志。
- 停止脚本仅处理本项目 `.runtime/dev-processes.json` 记录的PID，并匹配创建时间和可执行文件路径；不会停止MySQL或其他Java/Node，不会强占端口。未由脚本启动的IDEA/Vite实例需要在其原窗口停止。
- 本地停止通过结束指定进程实现，开发时请先完成页面保存操作，不要在写入中停止。
- 项目移动目录前先停止。脚本使用自身目录解析路径，不依赖当前终端位置或个人盘符。

手工开发方式仍支持：后端目录 `mvn spring-boot:run`，前端目录 `pnpm dev`。

回归测试：后端目录 `mvn test`，或调用 `.runtime/tools/apache-maven-3.9.9/bin/mvn.cmd`，按测试配置提供 DB 与 JWT 环境变量；前端目录运行 `pnpm build`。历史测试数量不是当前测试总数，运行结果以当次命令输出为准。

## 【Compose 部署配置：P12-D 待验收】

### 1. 目标机器环境

Windows安装并启动 Docker Desktop，使用 Linux containers，按安装提示启用WSL2/虚拟化；Linux可以使用Docker Engine和Compose插件。确认 `docker version`、`docker compose version` 可用。无需安装IDEA、Maven、Java、pnpm、MySQL或Workbench。

完整复制/获取项目，包括backend、frontend、sql、Dockerfile和docker-compose.yml，不要只复制dist。项目可放任意目录。根目录Compose使用相对路径。

### 2. 首次配置

在项目根目录复制示例文件；以下为待 P12-D 验收的配置步骤：

```powershell
Copy-Item .env.example .env
```

用编辑器打开 `.env`，替换 MYSQL_ROOT_PASSWORD、DB_PASSWORD、JWT_SECRET 的所有示例值。两个数据库密码应不同，使用足够长的随机值；JWT 密钥至少 32 位随机 ASCII 字符。需要 AI 辅助组卷/阅卷时同时填写 AI_BASE_URL、AI_API_KEY、AI_MODEL；需要在空库首次启动时创建 ADMIN，则同时填写 ADMIN_USERNAME、ADMIN_INITIAL_PASSWORD、ADMIN_NAME。

Compose中的DB_PASSWORD对应容器内专用数据库用户 `smart_exam`，不是本机root密码，也不必与MYSQL_ROOT_PASSWORD相同。该用户只使用smart_exam库，后端不使用数据库root。不要把现有本机密码复制进共享文件。

如果秘密含 `$` 或 `#`，在 `.env` 中用单引号包住整个值，避免Compose插值/注释；不要运行或分享会展开秘密的 `docker compose config` 输出。配置检查使用 `docker compose config --quiet`。

根目录 `.env` 只供Compose使用，不会打包进任一镜像，禁止提交Git。运行Compose前确认当前终端没有同名开发DB_PASSWORD/JWT_SECRET环境变量：进程变量会覆盖 `.env`，可以在新终端运行，或仅清除当前进程中的同名变量。

### 3. 构建并启动

```powershell
docker compose up -d --build
docker compose ps
```

首次下载镜像和依赖可能较慢。等待mysql、backend、frontend都为healthy后，打开 **http://localhost**。80占用时在 `.env` 设置 `HTTP_PORT=8088`，入口就变为 http://localhost:8088。

- mysql：配置使用官方 MySQL 8.4，首次空卷挂载 `sql/init.sql`，目标是创建 19 张表及基础 seed；这一容器路径尚待 P12-D 实测。
- backend：Java17，数据库地址使用服务名mysql，绝不使用127.0.0.1访问其他容器。
- frontend：Node构建阶段生成dist，最终镜像只有Nginx静态服务，不运行pnpm dev；`/api/`代理到backend，Vue路由刷新回退index.html。
- 配置的启动顺序：MySQL 健康检查 → 后端健康检查 → 前端。当前 Compose 的 MySQL 健康检查只抽查 9 张基础表，不等同于 19 张完整 schema 验收；完整空卷检查留待 P12-D。MySQL 和后端不映射宿主机端口，只有前端映射 80。
- `/actuator/health`只用于后端运维，返回UP/DOWN且不展示详情；Nginx不转发此路径。

新 Docker 数据库预计只有初始化 seed，不会自动复制本机已有演示考试。初始化的开发账号只适合受控演示；正式公网使用前必须更换演示账号凭据、配置 HTTPS 和备份策略。容器部署及这些使用流程尚未通过 P12-D 实际验收。

### 4. 停止、重启和保留数据

```powershell
docker compose down
docker compose up -d
```

普通down移除容器和网络，**不删除mysql_data命名卷**；重启复用数据库，已有数据不会重新初始化。容器配置为unless-stopped，Docker服务启动后会恢复未被主动停止的容器。

**危险：`docker compose down -v` 会删除数据库卷及其中数据！没有确认备份不要执行。**

数据卷属于当前电脑的Docker，不会随着代码复制到另一台电脑。如需迁移现有数据，需要单独备份/恢复MySQL。项目固定Compose名smart-exam；同电脑部署多套时使用不同 `docker compose -p <名称>` 和HTTP_PORT，并始终用相同名称管理对应实例。

修改 `.env` 密码不会修改已有数据库账户密码；已有卷改密需要先进行数据库账户改密，再同步环境配置。不要用删卷代替改密。初始化SQL是首次建库脚本，不承担后续数据库版本迁移。

### 5. 日志与故障排查

```powershell
docker compose ps
docker compose logs --tail=100 mysql
docker compose logs --tail=100 backend
docker compose logs --tail=100 frontend
docker compose logs -f backend
```

| 问题 | 处理 |
|---|---|
| docker不存在/无法连接daemon | 安装并启动Docker Desktop，确认Linux containers/WSL2正常 |
| 镜像/依赖下载失败 | 检查Docker网络、代理和仓库访问，不改业务代码 |
| 80占用 | 改HTTP_PORT，不改容器内8080 |
| 5173连接被拒绝 | 开发模式启动Vite；Docker模式访问80而不是5173 |
| using password: NO / JWT_SECRET缺失 | 补齐环境变量；IDEA配置不会自动传给终端 |
| Access denied | 检查应用密码、环境覆盖和已有数据卷账户密码是否一致 |
| Unknown database/缺表 | 检查mysql日志；新卷首次SQL是否完成，不要直接删除已有卷 |
| backend unhealthy | 检查DB_HOST=mysql、健康端点和数据库日志 |
| API 502 | backend尚未就绪或已停止，检查后端健康；不要把代理改为宿主localhost |
| 刷新teacher/student/login失败 | 确认使用本项目Nginx配置，不能仅裸露dist目录 |
| start-dev提示端口占用 | 先停IDEA或旧Vite实例；脚本不会杀掉它们 |

## 验证边界

截至 P12-C，仅已完成 P12-B 的独立 MySQL 空库与 Backend 验收。不能将 Compose 配置视为镜像 build、容器 up、Nginx 路由及卷持久化已经通过。P12-D 需在真实容器中验证：构建启动 → 19 张表 → 登录页 → 教师/学生登录 → `/api/auth/me` → 教师课程/考试页面 → 创建演示数据 → down → up → 确认数据仍在。

参考：[Docker启动依赖与健康检查](https://docs.docker.com/compose/how-tos/startup-order/)、[官方MySQL镜像初始化说明](https://hub.docker.com/_/mysql)。
