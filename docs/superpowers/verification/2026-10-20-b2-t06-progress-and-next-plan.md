## 下一步：按依赖顺序完成 T07—T09

### T07：自动保存和草稿恢复

1. 先实现与页面分离的答案保存队列：停止输入 1000ms 后保存；同题串行、不同题最多 3 个并发；revision 区分每次编辑，旧响应不得覆盖新输入。
2. 暂时性网络错误最多重试两次，分别等待 2 秒和 5 秒；401、403、已交卷、截止等业务拒绝停止自动重试，并提供明确状态。
3. 会话草稿按用户 ID 和答卷 ID 隔离。先向服务端确认仍可作答，再提示是否恢复；存储不可用时输入仍可继续，但必须显示不能保存本地草稿。
4. 页面展示未保存、保存中、失败、已保存；保留主动重试入口。成功交卷清理本卷；主动退出或切换身份清理原用户草稿。

验收：可控时钟/延迟响应测试先失败再通过；隔离浏览器检查连续输入、断网重连、刷新恢复、存储失败和另一学生登录。队列测试、前端全套逻辑测试与构建都通过后单独提交。

### T08：交卷屏障和会话恢复

1. 用户确认交卷后锁定编辑，先等待最新 revision 全部保存，再调用交卷。任一题失败即留页；禁止重复交卷请求。
2. 脏数据离开路由或关闭页面时提示；成功交卷后不再弹未保存确认。浏览器关闭提示由浏览器控制，不能保证自定义文案。
3. 会话过期时暂停队列并保留恢复条件；登录返回地址只接受应用内部安全路径。同一身份重新登录后重新查询答卷状态，其他身份不能接管原答卷。
4. 服务端截止是硬边界。到期冻结输入并查询当前状态，展示主动/自动交卷回执或待确认状态以及未保存题数，截止后不补写答案。

验收：保存失败绝不调用 submit，延迟响应仍等待最新草稿，重复点击只提交一次，401 停止队列，恶意 returnTo 被拒绝；独立短时场次检查到期、断网和身份切换。不能把编译后的处理器模拟称为浏览器 E2E。

### T09：时间锚点与开考边界刷新

1. 倒计时由 T06 的服务端锚点和单调计时计算；不再用本机墙上时间直接决定交卷资格。
2. 开考、首次入场截止和结束附近刷新；页面重新可见时同步，保留手动刷新入口。没有活动考试时不进行高频请求。
3. 同一页面只保留一组计时器；卸载清理；旧请求响应不得覆盖新状态。刷新失败保留上次数据，并显示更新时间和错误。

验收：客户端时间快/慢 5 分钟、到期归零、重新同步、隐藏后恢复、重复计时器和乱序响应；隔离短时考试实际等待开考，确认入场按钮出现及截止后状态同步。
