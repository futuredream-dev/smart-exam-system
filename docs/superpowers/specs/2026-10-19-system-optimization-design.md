## 1. 本次交付与目标

本次交付更改报告、实施计划和环境基线记录。目标是在保留现有业务与数据的基础上，修复答案和评分保护问题，简化教师任务入口，统一考试阶段，提升题库、阅卷和学生作答的连续使用体验。

采用“现有系统增量优化”：继续使用 Java 17、Spring Boot、MyBatis-Plus、MySQL、Vue 3、Vue Router、Axios 与现有样式体系；不更换框架、不重建整个系统、不借机升级所有依赖、不引入微服务。

用户已要求先完成报告和计划，并保护现有环境。本轮仅新增规划文档，不执行实施计划，不创建测试数据、不安装依赖、不启动第二套服务，也不提交或推送 Git。

## 4. 环境保护与兼容契约

### 4.1 当前环境保护

1. 本轮只新增 `docs/superpowers/specs/`、`plans/`、`baselines/` 中明确列出的文档。
2. 保留当前主工作区、三个原有未跟踪资料、本地配置、`.runtime/`、已安装工具和正在运行的服务；不执行 `git clean`、强制重置、批量暂存、原目录覆盖或按端口杀进程。
3. 后续实施优先在托管 worktree 的 `codex/system-optimization` 分支进行；创建前检查已附加 worktree，使用本轮确认的基线提交，不假定远程默认分支包含本地全部资料。原有未跟踪题库资料不会自动复制，不将其加入实现提交。
4. 测试使用独立数据库名，例如 `smart_exam_opt_test_20261019`，和仅获该测试库权限的账号。每次写测试前验证实际数据库名；仅设置环境变量不算验证。
5. 原 `init.sql`/`demo-data.sql` 内含固定数据库指向。不得直接用 `mysql 新库 < 原脚本` 认为已隔离。先制作仅用于隔离库的副本，逐条核对 CREATE/USE、限定库名、外键与 seed，确认不会触及现有库后才运行。
6. 原开发入口固定检查 8080/5173/3306，暂不修改该契约。并行验收若获准，使用独立工作区的显式后端 18080、前端 15173，执行时先检查端口可用，Vite 使用 strictPort 与 `VITE_API_PROXY_TARGET=http://127.0.0.1:18080`。不调用原目录的 start/stop 脚本启动并行实例。
7. 测试配置由执行时的受控会话提供，不覆盖 `config/local.env`，不在文档、命令参数、截图或日志中打印真实凭据。测试 Token、备份与临时密码不进入 Git。
8. 文件清理或 worktree 归档时先解析绝对路径，确认属于当批独立目录，保留仍需要的输出。任何数据库恢复只指向独立恢复验证库；原业务库切换属于最终发布步骤。

### 4.2 保留的业务不变量

- ADMIN/TEACHER/STUDENT 服务端角色授权和教师课程所有权继续生效；界面隐藏不能代替权限检查。
- 已发布试卷、评分点和应考名单继续使用快照，题库或课程名单后续变动不改写历史考试。
- 单选题由服务端评分，简答题最终分由教师确认；AI 分数不直接变成正式成绩。
- 已交答卷不重新开放；已发布成绩继续只读，受控纠错未设计和批准前不加入普通改分入口。
- 考试复制和补考不复制答案、成绩或行为记录；归档不删除历史数据。
- 保留现有 API 响应外层、旧路由和旧列表行为。新增字段和端点优先采用兼容方式；明确的安全行为变化单独说明。
- `ExamStatus` 的数据库枚举不因 UI 阶段调整而扩展或批量改写；归档仍使用 `archived_at`。

## 5. 教师端目标界面

### 5.1 一级导航与现有入口迁移

一级导航保留“工作台、考试管理、题库管理、课程管理”。工作台提供跨考试待阅列表；阅卷任务页面和直达链接保留兼容，但不再与考试入口形成重复的一级入口。AI评分分析移入对应考试的成绩分析，保留原地址的可用性和明确返回路径。

不删除现有功能。旧入口使用明确的跳转或深链，保留 examId、分页和筛选上下文；重定向不丢失考卷定位，也不创建导航循环。

### 5.2 工作台

默认显示“待阅答卷、即将开考、待发布成绩”三类任务，每类最多 5 场，展示总量和查看全部入口。进行中考试作为需要关注的场次展示。零答卷且无人参考的考试不列入待发布成绩催办任务。摘要数字与点击后的列表使用同一统计定义。

页面不默认堆积所有历史场次。验收数据保留；以后使用独立演示库维护展示内容，不能为页面整洁删除现有库数据。

### 5.3 考试详情

页头只保留名称、课程、阶段、时间和一个主要动作。详细规则、题型和统计放入对应区域，避免重复大块摘要。

内部栏目：“概览、试卷、考生与考务、阅卷、成绩”。草稿优先配置试卷与名单；待开始显示安排；进行中优先考务；结束后优先阅卷；阅完优先发布；发布后优先成绩分析。只读栏目始终可访问，未到阶段的操作给出原因。

列表页在有输入、加载、错误、空数据、筛选无结果等状态都保留明确动作。阶段不只靠颜色表达，按钮与表单具有可访问名称和键盘焦点。

### 5.4 组卷与题库

组卷一级选择“从题库组卷、手动出题”；从题库进入后展示“人工选题、随机、按规则、AI 辅助”及各自说明，不改变后端确定性校验与人工确认。

题库默认摘要列表：题名、题型、难度、章节、分值、状态。题干、选项、答案和评分点按需展开。默认排除归档题目；筛选支持重置、URL 保留、每页 20 条，页大小允许 20/50/100。

批量选择以明确 ID 集合管理，最多 200 道；跨页保留选择并显示数量，切换筛选不静默清空。已归档或失效 ID 的提交由服务端逐项校验并提示，不能错误修改其他题目。

### 5.5 阅卷

保留“答卷内容＋评分操作”布局。当前题、未保存题数、保存中、失败状态清晰可见。每次 API 返回仅更新成功保存的字段基线，其他题脏值保持不变；相同答卷的 AI 刷新不覆盖教师输入，不同答卷的草稿不串用。

“保存并下一份”必须先保存整份答卷所有脏字段；保存失败留在当前答卷，未评分题需要教师明确确认，不能把默认 0 分默认为已复核。AI 处理不作为跳过人工复核的依据。

## 6. 核心行为更改设计

### 6.1 选项兼容

保留题库已经允许的 2—20 个唯一非空选项标识；学生提交非空答案时，校验是否精确属于该题快照中的标识。空答案继续允许。既有手动出题四选一表单继续使用 A—D，不强迫所有历史题目改写，也不自动重标历史选项。发布前再次检查选项唯一性和正确答案归属。

### 6.2 题库归档与恢复

归档库保留课程绑定，作为可恢复资源展示。新增归档筛选和恢复入口，不删除、不自动释放课程占用。恢复后原课程与题目状态保持不变。若历史数据存在绑定冲突，返回业务冲突并保留归档状态。课程替换题库属于后续独立需求，不隐式迁移题目。

### 6.3 学生答案保存与交卷

- 输入停止 1000ms 后触发自动保存；每题单独串行队列，允许不同题并行但限制同时最多 3 个请求。
- 使用递增 revision 标识草稿版本，旧响应不覆盖较新输入。保存按钮继续作为主动重试入口。
- 仅暂时性网络错误自动重试两次，延迟 2 秒和 5 秒；401、403、已交卷、超时截止等业务拒绝不循环重试。
- 会话内草稿按用户 ID＋答卷 ID 隔离，采用 sessionStorage；存储失败显示提示，不阻断输入。恢复时先验证服务端仍允许该用户作答，再比较本地/服务端并提示恢复，不能静默覆盖新数据。
- 用户确认交卷后暂时锁定编辑，等待所有最新草稿保存成功，再调用交卷；任一失败则留页并列出失败题。
- 服务端截止仍为硬边界，不补录截止后的答案。到期冻结编辑、查询交卷状态并显示回执及未保存数量，不根据本机时间直接跳走。
- 离开页面存在脏数据时提示，退出或切换账号清理该账号会话草稿；成功交卷清理本答卷草稿。

### 6.4 时间、状态与出分

Paper 增加 `serverNow`、`deadlineAt` 两个 ISO 8601 UTC 时间字段，保留原时间字段；截止时间从现有北京时间解释为绝对时间。前端以服务端锚点和单调计时显示倒计时，页面恢复可见时重同步。

抽取统一考试阶段投影，包含无参与结束状态 `NO_PARTICIPANTS`。它仅描述 UI，不扩展数据库枚举。零答卷场次不提供“发布空成绩”作为常规动作；管理员与教师页面使用同一实时阶段，原 `status` 字段保留业务含义。

发布检查至少阻断 `endTime <= now`；进行中临时发布的行为本批保留但显示警示，不在本次缺陷修复中无提示地改成全面禁止。

### 6.5 AI、上传与会话

AI 后端默认时限保持 30 秒，AI 阅卷前端 40 秒，AI 组卷前端保留 65 秒，代理读取时限设为 70 秒。前端对同一答案在途请求禁止重复触发，超时后先读取结果状态；暂不引入消息队列。长事务/锁占用须在隔离复现后决定是否分离“验证—模型调用—加锁持久化”，不可在未校验成绩已发布的情况下回填结果。

学生 Excel 业务上限 5MiB，题库 1MiB；Spring 单文件上限 5MiB、请求上限 6MiB，Nginx 请求上限 6MiB，前后端错误文案与业务限制一致。

过期会话进入统一重新认证状态并暂停后台自动保存；只允许返回同源应用内部路径，同一用户重新登录后再恢复答卷。B4A 增加账号 tokenVersion，改密/重置递增并使旧 Token 失效；账号从启用变为停用时也递增，重新启用不能让停用前 Token 复活。改密成功后明确要求重新登录，不擅自延长 JWT 有效期。

## 10. 回滚与上线边界

- 每批一个可独立审阅的提交集合，只暂存明确文件；原本未跟踪资料不进入提交。
- 原工作区在用户确认发布前不接入新库/新进程，不切换默认访问入口。开发验证在独立工作区完成。
- 无 schema 改动的批次通过代码版本与构建产物回退；本地草稿格式有版本号并能丢弃不兼容记录，不改写服务端成绩。
- schema 变更先在独立库备份/升级/恢复演练；新增 tokenVersion 等采用兼容增量，不直接 DROP 列。代码回退前检查旧版是否仍可读新 schema。
- 数据迁移前检查连接目标、表结构、影响行数及备份可恢复性；失败暂停该批，不能连跑其他升级脚本求修复。
- 新方案经过验收后，才准备具体发布清单和原环境切换步骤；不能把“计划批准”解释成立即重启现有服务。
