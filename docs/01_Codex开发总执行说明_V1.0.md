# Codex 开发总执行说明 V1.0

## 固定需求
- 题型：仅 `SINGLE_CHOICE` + `SHORT_ANSWER`，第一版不新增。
- 迟到：按 `lateEntryMinutes`（开考后多少分钟允许首次进入）。
- 主动交卷：按 `minSubmitMinutes`（开考后多少分钟允许主动交卷）。
- 学生答案：第一版仅基础一次性提交，不做自动暂存/断线答案恢复。
- AI：第一版仅 AI 辅助阅卷。
- 学生成绩：只显示总分 + 教师评语；AI反馈后续再加。

## 核心业务
教师创建课程 → 加入学生 → 创建考试 → 设置规则 → 添加题目/参考答案/评分点 → 发布 → 学生进入 → 答题 → 提交/自动交卷 → 选择题自动判分 + 简答题AI建议 → 教师复核 → 总分/教师评语 → 发布 → 学生查看。

## Codex 边界
1. 先检查当前仓库，沿用现有技术栈和项目骨架。
2. 数据库和 API 以另外两份 V1.0 文档为准。
3. 不擅自新增题型、自动暂存、AI出题、复杂统计、学生AI反馈。
4. 每次只改一个阶段/模块，采用最小改动。
5. 修改前列文件清单，修改后运行测试并汇报。
6. 发现文档和现有代码冲突时先说明，不要直接重构整个系统。

## 开发顺序
1. 检查仓库并输出差异清单。
2. 登录/角色权限/统一响应/统一异常。
3. 课程 + 学生加入课程 + 考试 + 题目 + enter + 基础 submit。
4. 选择题自动判分 + 简答题AI辅助阅卷 + 教师复核。
5. 总分、教师总评、发布成绩、学生成绩页。
6. 迟到拒考、最早交卷、自动交卷、防重复提交、重新进入。
7. 页面状态/提示统一，完整业务链测试。

## 每次执行模板
请先阅读 `docs/` 下三份 V1.0 文档，并检查当前仓库。本次只完成指定模块。不得擅自修改已确认需求、数据库字段和 API 命名；保留现有可用代码，采用最小改动；开始前列出修改文件，完成后实际运行/测试并输出结果和遗留问题。
